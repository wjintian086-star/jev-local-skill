## 这是什么

一份从真实踩坑记录里提炼出来的 **SKILL 文档**：在 Android 手机上用 Termux + llama.cpp，跑起「判断层 + 生成层」双模型，让输入法 App 在**零云端、零外部 Key** 的条件下完成：

```
读对方消息 → 判 8 类意图 + 0-9 风险 → 起草候选 → 你手动插入
```

全程 `127.0.0.1`，不联网也能出结果。

## 为什么值得看

大部分"手机跑大模型"的教程止步于 `llama-cli` 能吐字。真正能日常用的形态是**输入法**——它不受 App 适配限制，微信、QQ、钉钉都能用，而且天然由你决定发不发。

这个仓库记录的是把它真正跑通的全过程，包括那些看文档发现不了的坑：

- **决策模型跑不起来**：llama.cpp 的 `/v1/systemone` 除了元数据，还要求 GGUF 自带 `tokenizer.chat_template.systemone`。缺这个模板，补元数据必 Exit 1 —— 无解，只能加兼容层。
- **GGUF 补丁把权重搞错位**：插入 46 字节后文件能加载，但张量起点差 14 字节，输出全错。正确做法是凑到 32 字节对齐的整数倍。
- **`/health` 会说谎**：上游 `/health` 不校验 API Key，所以旧版兼容层能"假通过"。
- **Key 留空会被静默换掉**：App 检测到空 Key 就直接走内置云端中转，你填的本地地址整个被丢弃。
- **配置页会自己改回默认值**：下拉框首次自动回调把自定义地址覆盖成预设第一项。

## 适用与不适用

**适合**

- 想在手机上做"离线消息意图识别 + 风险打分"的人
- 已有只认某种私有协议 / OpenAI 风格接口的客户端，想在本地造后端
- 想复刻或魔改输入法型 AI 项目（如 jev-simple）
- 正在被"服务起了但请求没反应"折磨的人 —— 直接看第 6 节排障阶梯

**不适合**

- 想要高质量长文生成（手机 4B 只能出短候选）
- 需要多轮对话记忆（这条链路是单条消息 → 单次判断）
- 想要自动回复（该形态明确设计为永不自动发送）
